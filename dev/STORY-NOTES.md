# /dev 故事脚本说明

本轮独立脚本在 `dev/stories.js`，不导入、不改写现有故事模块。三条故事各三章六幕，共 18 幕；每幕只交给孩子一个行动，每幕两个可触摸的具体提示。三条主题来自 `src/story-blueprints.js` 与 `STORY-BIBLE.md`，并参考 `HANDOF.MD` 中直白短句、语音自动推进、减少开场手续的方向。

| 故事 | 保留的原意 | 新版节奏 |
| --- | --- | --- |
| 送豆豆回家 | 先照顾迷路小狗；记住红屋顶、骨头门牌、小木桥；一起过河；平安交给妈妈 | 在“过桥”之前单独留一幕等豆豆准备好，让紧张被看见。找家时比较线索，不把两个按钮做成答题。 |
| 登月计划 | 自己发明出行装置；海底、巨人口袋、云层的温和偏航；连续改造；完成登月 | 保留发明和整支小队的连续性，增加抵达后的纪念幕。提示仅用于启发，自由讲述是同等、明确的入口。 |
| 不见了的回声 | 从河湾出发，经过萤火草地、月球、海底、巨人口袋、云洞；找到并陪回声回家 | 道具职责限定为听清、记路、照亮。每幕先让 NPC 彼此说两三句，再问孩子一个短问题；不追加命名或开口仪式。 |

## 剧本与引擎契约

- `STORIES` 是故事数组，`getStory(id)` 返回故事，未知 ID 回退豆豆线。
- 每幕的 `dialogue`、`closing` 是依序播放的单句，`speaker` 必须指向该幕角色 ID 或 `companion`。同幕最多两位 NPC；伙伴由引擎额外放置。
- `question` 只问一个眼前行动。`choices` 的 `hints` 供语音/文字匹配；`result` 由 `speaker` 说出，随后触发 `action`、显示道具，再进入 `closing`。
- `action` 使用 `listen`、`glow`、`bridge`、`launch`、`celebrate` 五种可见反馈。`expression` 可用于独立模型的脸部和姿态变化。
- `reward` 是可用的纪念物或道具，包含 `id`、`name`、`description`，没有分数或好坏评价。两个选择可以得到同一道具。
- 每幕完成后保留清晰的继续入口；语音期间可以跳过当前一句，不能让跳过误触同时替孩子作答。

## 登月自由发明

月线所有六幕设置 `freeInput: true`。`inventionHints` 是灵感例子，`inventionPrompt` 说明该幕需要解决的具体问题。引擎应保存每次真实回答到本次发明日志，并把前一幕发明带入下一幕。

`inventionResult` 是自由输入的连贯结果后备，配套字段为 `inventionAction`、`inventionSpeaker`、`inventionExpression`、可选的 `inventionReward`；`nextDestination` 标识下一站。引擎可把玩家的点子和这些约束交给已有故事接口生成简短回应，也可先复述真实回答，再播放后备结果。不要将所有自由回答自动匹配为第一个按钮，不要把“我想换个办法”误当成已决定出发。

月线的触摸提示同样是发明日志中的一次方案，应与自由方案共享后续的持续改造。海底蓝螺栓、口袋线、方向卡是当地角色提供的材料；自由回答可以得到同等材料，不能只给点选回答。

## 包容性与真实性调整

- 语音优先，触摸和文字后备同样能完成全部故事；不用大声说话，不把不说话解释为害怕或能力不足。
- 两个行动都能推进，不评分、不推断固定人格。陪伴也包括安静坐着、等一等、重复听一次和换条路。
- 豆豆线结尾只复述用户确实做过的照顾，不声称每个孩子都同时喂了苹果、给了水或走了桥。
- 回声线保留图鉴跨页的幻想设定；月球幕明确没有空气，声音来自通讯器和故事贝壳，不暗示月坑能在真空中产生可听回声。
- 登月着陆提示移除“月面开降落伞”，改为小推进器减速或明确的幻想传送门。幻想发明与现实实验不混在一起，也不提供燃烧、爆炸等现实操作方法。
- 回声不是被迫开口才获准回家；先尊重它的节奏，再陪它走。最后由小回声自己说“我回来啦”。

## 实际验收要点

验证三个故事各能完成六幕；每个按钮有对应结果；地图、人物、句子、章节随幕切换；最后一幕进入本线结局。验证月线一个非提示的自由发明能被保留到后续幕，不强制改成火箭或传送门。验证没有麦克风、语音失败或希望安静体验时仍能继续。故事运行不得加载旧骨骼角色资源。
