# 游戏模块维护

- 改动三个主章节前先读 `ARCHITECTURE.md`。剧情台词、输入方式、分支与事件放在 `content/`；不要把 Three.js 工厂、DOM 或网络请求放进脚本。
- 用稳定场景 ID 维护进度；调整顺序保留 ID。新增剧情效果先使用 `runtime/contracts.js` 中已有命令；新能力须同时增加契约、运行器、表现实现和测试。
- 语音与模型结果调用同一命令入口。模型提案必须经过 `intent-gateway` 的资源校验和上下文检查；不执行返回的代码，不直接改 DOM、模型对象或主线进度。
- 新道具写独立 `modules/props/<id>.js`，登记 `registry.js` 和 `content/props.js`，真实实现声明的互动和动画，提供清理。
- 新的公共 UI、逻辑模块必须更新 `modules/catalog.js` 的用途、源码、能力和依赖；同时提供可试用演示或准确说明验证入口。模型、世界、彩蛋和音频由资源表/构建扫描自动登记。
- 模块新增、删除、改名或能力变化，都要更新模块陈列馆和机器可读清单。不要直接编辑 `audio.generated.js`、`catalog.json` 和各 bundle；运行构建生成。
- 运行 `node dev/tools/build.mjs`（含目录一致性检查）和 `node dev/tools/verify-game-runtime.mjs`。影响流程时运行三章浏览器检查，影响陈列时运行陈列馆浏览器检查；本地预览使用独立浏览器会话。
- 保留旧导入路径的兼容出口和现有存档。陈列馆试验不读写玩家进度；所有音频按用户点击播放，切换条目停止。
- 默认发布约定沿用用户授权；用户当次的明确范围优先。
