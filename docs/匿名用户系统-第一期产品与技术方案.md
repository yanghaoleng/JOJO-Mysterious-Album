## 2. 项目现状

- 项目目前没有数据库。
- 没有用户身份、登录、会话或权限系统。
- 项目已有独立的 `/Data` 匿名访问统计页，但在本期之前没有用户管理后台。`dev/modules/` 是模块陈列馆，不是管理后台。
- 服务端由 `api/` 下的无状态 Serverless API 组成，目前主要转发 AI、ASR 和 TTS 请求。
- 三章故事进度、旅程、儿童偏好画像和角色实验室数据目前保存在浏览器 `localStorage` 中，不会跨设备同步。

## 3. 已确认的产品决策

### 3.1 第一期目标

1. 浏览器访问产品时自动注册匿名用户。
2. 用户无需看到或操作注册流程。
3. 同一浏览器在会话有效期内可恢复同一匿名用户。
4. 提供受保护的后台管理页面，管理员可查看匿名用户。
5. 身份服务暂时不可用时，不影响现有游戏进入和游玩。

### 3.2 第一期不做

- 不同步三章故事进度、角色、儿童画像、语音或其他业务数据。
- 不改造现有 `localStorage` 存档。
- 不做手机号、邮箱、密码、第三方登录或家长账号。
- 不做跨浏览器或跨设备恢复。
- 不做用户行为分析、留存分析或用户标签。
- 不在后台展示 IP、精确位置、浏览器指纹、语音或儿童输入内容。
- 第一版后台为只读，不提供禁用用户、删除用户或撤销会话的界面操作。

### 3.3 产品体验边界

- 首页页脚低调显示完整匿名用户 ID，用于内测问题定位；其他普通页面不展示注册状态或会话技术信息。
- 首页公共入口在页面加载后异步初始化身份，游戏启动不等待初始化完成。
- 清理 Cookie、使用隐私浏览、更换浏览器或设备，将被视为新匿名用户。
- 第一期不向用户承诺匿名账户可恢复。

## 4. 技术决策

### 4.1 数据库

第一期使用 **MySQL 8.0+**。本地开发已确定使用 Docker MySQL 8.4.7；共享测试和生产应使用支持 TLS、自动备份和连接数限制的托管 MySQL，具体供应商不在本阶段锁定。

Serverless 环境需配置连接池或供应商的 HTTP/Data API，不能让每个函数实例无限创建长连接。

本地开发阶段先使用本机 MySQL：

- Host：`127.0.0.1`
- Port：`3306`
- User：`root`
- Password：`root`
- Database：`jojo_mysterious_album_dev`

`root/root` 仅用于本地开发，不得复用到共享测试、预发布或生产环境。共享及生产环境必须使用独立的最小权限数据库账号。

### 4.2 身份与 Cookie

- 服务端使用密码学安全随机数生成会话令牌。
- 浏览器只通过 Cookie 保存令牌，不将令牌或长期 JWT 写入 `localStorage`。
- Cookie 名称使用 `__Host-jma_session`。
- Cookie 属性为 `HttpOnly; Secure; SameSite=Lax; Path=/`，不设置 `Domain`。
- MySQL 只保存令牌的 SHA-256 等安全哈希，不保存原始令牌。
- 普通前端 JavaScript 无法读取会话 Cookie。
- 会话默认有效期为 90 天，有效访问可滑动续期，单个会话最长存活 180 天。

### 4.3 活跃时间

- 完成身份初始化时记录用户与会话的 `last_seen_at`。
- 为避免每次请求都写数据库，仅当距离上次活跃超过 10 分钟时更新。
- 后台中的“在线”是产品统计口径：最近 10 分钟内活跃，不代表持续网络连接。

## 5. 用户流程

### 5.1 首次访问

1. 公共前端模块调用 `POST /api/auth/anonymous`。
2. 服务端未发现有效会话，在一个事务中创建 `users` 和 `sessions` 记录。
3. 服务端设置会话 Cookie，返回最小用户摘要。
4. 前端不展示额外 UI，游戏流程不受影响。

### 5.2 再次访问

1. 浏览器自动携带 Cookie。
2. 服务端哈希令牌并查找未撤销、未过期会话。
3. 返回原匿名用户，必要时更新活跃时间和 Cookie 到期时间。

### 5.3 并发标签页

前端优先使用 Web Locks API，以 `jma-anonymous-bootstrap` 为锁名串行执行身份初始化。不支持 Web Locks 的浏览器使用短时 `localStorage` 租约作为退化方案。该机制只用于减少首访并发创建，不作为身份凭证。

## 6. API 设计

### 6.1 匿名身份初始化

```http
POST /api/auth/anonymous
Content-Type: application/json
```

请求体为空 JSON 对象。接口必须幂等：已有合法 Cookie 时恢复原用户，不重复创建。

```json
{
  "user": {
    "id": "0199f0a8-1234-7abc-8def-0123456789ab",
    "kind": "anonymous"
  },
  "session": {
    "expiresAt": "2026-12-19T08:00:00.000Z"
  }
}
```

不向普通前端返回会话令牌。接口返回当前匿名用户 UUID，仅用于首页页脚内测定位；UUID 不是认证凭据，不能替代 HttpOnly 会话 Cookie。

错误响应使用稳定错误码：

```json
{ "error": "identity_unavailable" }
```

前端收到失败后仅记录脱敏诊断，不阻塞游戏，可在后续页面加载时重试。

### 6.2 管理员登录与退出

```http
POST /api/admin/login
POST /api/admin/logout
```

第一期使用单个内部管理员凭据：

- `ADMIN_USERNAME`
- `ADMIN_PASSWORD_HASH`
- `ADMIN_SESSION_SECRET`

环境变量只保存强密码的 scrypt 哈希，不保存明文密码。登录成功后设置独立的短期 `HttpOnly` 管理会话 Cookie，不复用普通匿名用户 Cookie。

### 6.3 用户列表

```http
GET /api/admin/users?page=1&pageSize=50&status=active&activity=online&sort=created_desc
```

约束：

- `pageSize` 默认 50，最大 100。
- 支持按注册时间、最近活跃时间排序。
- 支持按状态和在线/非在线筛选。
- 支持完整用户 ID 精确搜索，不做模糊枚举。
- 所有响应设置 `Cache-Control: no-store`。

返回字段：

```json
{
  "items": [
    {
      "id": "0199...",
      "kind": "anonymous",
      "status": "active",
      "createdAt": "2026-09-20T08:00:00.000Z",
      "lastSeenAt": "2026-09-20T09:10:00.000Z",
      "online": true,
      "activeSessionCount": 1,
      "latestSessionExpiresAt": "2026-12-19T09:10:00.000Z"
    }
  ],
  "page": 1,
  "pageSize": 50,
  "total": 1
}
```

### 6.4 用户详情

```http
GET /api/admin/users/:id
```

展示用户基本时间信息和会话列表。会话只显示会话 ID、创建、最近活跃、到期和撤销时间；不返回 `token_hash`。

## 7. MySQL 数据模型

实现时应通过版本化 migration 创建表，不在线上手工改表。以下 DDL 是约束基线，具体 migration 可根据选定的 MySQL 客户端调整命名和时间精度。

```sql
CREATE TABLE users (
  id BINARY(16) NOT NULL,
  kind ENUM('anonymous') NOT NULL DEFAULT 'anonymous',
  status ENUM('active', 'disabled') NOT NULL DEFAULT 'active',
  created_at DATETIME(3) NOT NULL,
  last_seen_at DATETIME(3) NOT NULL,
  PRIMARY KEY (id),
  KEY idx_users_created_at (created_at, id),
  KEY idx_users_last_seen_at (last_seen_at, id),
  KEY idx_users_status_created_at (status, created_at, id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;

CREATE TABLE sessions (
  id BINARY(16) NOT NULL,
  user_id BINARY(16) NOT NULL,
  token_hash BINARY(32) NOT NULL,
  created_at DATETIME(3) NOT NULL,
  last_seen_at DATETIME(3) NOT NULL,
  expires_at DATETIME(3) NOT NULL,
  absolute_expires_at DATETIME(3) NOT NULL,
  revoked_at DATETIME(3) NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uq_sessions_token_hash (token_hash),
  KEY idx_sessions_user_active (user_id, revoked_at, expires_at),
  KEY idx_sessions_expires_at (expires_at),
  CONSTRAINT fk_sessions_user
    FOREIGN KEY (user_id) REFERENCES users(id)
    ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

应用层对外显示 UUID 字符串，MySQL 使用 `BINARY(16)` 索引。转换必须集中封装，避免后台搜索和 API 序列化出现字节序不一致。

## 8. 后台管理页面

### 8.1 路由

- `/admin/login/`：管理员登录。
- `/admin/users/`：匿名用户列表。
- `/admin/users/?id=<uuid>` 或独立详情路由：用户与会话详情。

### 8.2 列表字段

- 短用户 ID，例如 `a81f…29cd`，可复制完整 ID。
- 用户类型。
- 用户状态。
- 注册时间，界面按北京时间展示。
- 最近活跃时间。
- 在线标记。
- 有效会话数。
- 最近会话到期时间。

### 8.3 空状态与错误状态

- 没有用户时明确显示“暂无匿名用户”。
- 筛选无结果时保留筛选条件并提供清除入口。
- 会话失效返回登录页，不展示后台数据残留。
- API 失败时显示可重试状态，不把数据库错误或堆栈暴露给页面。

## 9. 安全与隐私

- 所有身份和后台接口只通过 HTTPS 访问。
- 只接受同源请求；所有修改类请求校验 `Origin`。
- 管理员登录需按 IP 和用户名限流，失败响应不区分用户名错误或密码错误。
- 匿名注册接口按 IP 做宽松限流，但不将 IP 保存为用户资料。
- 日志不记录 Cookie、原始会话令牌、密码、管理员密码哈希或完整请求头。
- 后台和身份响应使用 `Cache-Control: no-store`。
- 数据库账号仅授予应用所需最小权限，连接密钥只存在服务端环境变量。
- 生产和测试使用独立数据库，不复制真实用户数据到本地。

```dotenv

SESSION_TOKEN_PEPPER=replace_with_a_long_random_secret

```

如托管 MySQL 使用拆分的 host、port、user 和 password 变量，实现可替换 `MYSQL_URL`，但不改变本文档的数据模型与安全边界。

## 11. 可观测性

第一期只记录服务健康所需的脱敏指标：

- 匿名身份初始化成功率和延迟。
- 创建新用户数量。
- 恢复已有会话数量。
- 数据库连接与查询错误数量。
- 后台登录成功/失败数量。

指标不带会话令牌、完整用户 ID 或儿童业务数据。

## 12. 验收标准

### 12.1 匿名用户

- 新浏览器首次访问后，MySQL 中生成一个匿名用户和一个有效会话。
- 刷新页面或重新打开同一浏览器，恢复原用户而不是创建新用户。
- 同时打开多个标签页时，支持 Web Locks 的目标浏览器不重复创建用户。
- Cookie 无法被 `document.cookie` 读取。
- 过期、撤销或不合法令牌不能恢复会话。
- MySQL 中不存在原始会话令牌。
- 数据库或身份 API 失败时，现有首页和三章游戏仍能进入。
- 第一期不上传任何现有 `localStorage` 业务数据。

### 12.2 管理后台

- 未登录访问管理页不能取得用户数据。
- 普通匿名 Cookie 不能访问管理 API。
- 管理员可分页查看用户，并按状态、活跃情况筛选。
- 列表可按注册和最近活跃时间排序。
- 管理员可使用完整用户 ID 精确查找用户。
- 用户详情可查看会话时间和状态，不显示会话令牌或哈希。
- 所有后台 API 响应都不被浏览器或 CDN 缓存。
- 桌面与手机尺寸下均可完成登录、列表查看、筛选和退出。

## 13. 实现时的模块边界

预期拆分如下，具体文件名可在实现评审时微调：

- 数据库连接与 migration：独立服务端模块。
- 随机令牌、Cookie 和会话校验：独立身份模块。
- `api/auth/anonymous.js`：只负责匿名初始化端点。
- `api/admin/*`：管理员登录和只读查询。
- 公共前端 bootstrap：只负责发起无感初始化，不读写现有游戏存档。
- `admin/`：独立的登录、用户列表和详情页，不复用儿童游戏页面的业务状态。

新的公共模块实现时必须按 `dev/AGENTS.md` 更新模块陈列馆和机器可读清单。如果实现对用户可见，同日更新 `src/changelog/entries.json` 的中文摘要。

## 14. 后续阶段的兼容预留

第一期的数据结构需保留以下扩展能力，但不在本期实现：

- 将匿名用户原地升级为正式用户，尽量保持同一 `user_id`。
- 同一用户管理多个设备会话。
- 新增用户文档表，同步故事进度和作品。
- 后台新增会话撤销、用户禁用和数据删除功能。
- 增加用户数据导出、删除和保留期策略。

后续阶段不应将业务数据直接塞入 `users` 或 `sessions` 表，避免身份层与游戏数据耦合。
